WHAT CHANGED FROM THREE-BOT TO TWO-BOT

BEFORE (Three Separate Bots):
  ❌ Jelly Guardian bot (moderation) → token in .env
  ❌ Backup Bot (backups) → token in .env
  ❌ Restore Bot (restore) → token in .env (persistent)
  ❌ Three tokens to manage
  ❌ Three .env files
  ❌ Restore bot always has attack surface

  ✅ Jelly Guardian + Backup combined → token in .env (required)
  ✅ Restore Bot offline → NO token (zero attack surface)
  ✅ One active token to manage
  ✅ One .env file
  ✅ Restore bot is offline until needed
  ✅ Simpler, safer, more elegant

HOW IT WORKS

JELLY GUARDIAN + BACKUP BOT (One Bot, Two Roles)

  📍 Always Running (24/7)
  📍 Token stored in .env
  📍 Permissions: Send + Delete Messages + Read History

  Role 1 — MODERATION:
  ├─ Monitors all messages in real-time
  ├─ Analyzes with GPT (two-stage AI)
  ├─ Decides: REMOVE, CAUTION, or SAFE
  ├─ Deletes violations (if not in shadow mode)
  ├─ Logs all deletions with full content
  └─ Dashboard shows decisions in real-time

  Role 2 — BACKUP:
  ├─ Runs every day at 2 AM PST/PDT
  ├─ Backs up: Roles, channels, messages, emojis, webhooks
  ├─ Stores: data/backups/ (keeps 5 most recent)
  ├─ Accessible: /backup command (manual) or /getbackup (receive via DM)
  └─ Recovery ready: Can restore anytime

RESTORE BOT (Offline Until Needed)

  📍 NOT running by default
  📍 NO token stored anywhere
  📍 Invite link saved in documentation
  📍 Permissions: Administrator

  Emergency Workflow:
  1. Server is destroyed
  2. Get backup from Jelly Guardian Bot
  3. Click saved OAuth2 invite link
  4. Restore Bot joins server (temporary)
  5. Run: /loadbackup (upload backup file)
  6. Run: /restore (restores everything)
  7. After restore: Remove bot from server
  8. Restore Bot goes offline again (zero attack surface)

SECURITY MODEL

Attack Scenario 1: Jelly Guardian Token Stolen
  Attacker can:
    ✓ Delete messages (rate limiter catches it)
    ✓ Read message history
    ✗ Cannot ban, kick, or change roles
    ✗ Cannot access Restore Bot (it's offline)

  Detection: Rate limiter triggers in <60 seconds
  Max damage: ~100 messages
  Recovery: Regenerate token (5 minutes)

Attack Scenario 2: Restore Bot Invite Link Discovered
  Attacker can:
    ✓ Click the link (invites bot to server)
    ✗ Cannot delete the bot (that's admin-only)
    ✗ Cannot use bot (no persistent token)
    ✗ Cannot cause sustained damage (invite-only)

  Detection: Bot appears in server (obvious)
  Max damage: 0 (admin removes it immediately)
  Recovery: Create new invite link (5 min)

Attack Scenario 3: Lightsail SSH Compromised
  Attacker gets .env and finds:
    ✓ One token (Jelly Guardian)
    ✗ No Restore Bot token (it doesn't exist)
    ✗ Can't compromise what isn't stored

  Max damage: One bot compromised, not two
  Recovery: Regenerate one token (5 min)
